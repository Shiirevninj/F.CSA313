## 2. SLO

| Сценарио | SLI (юуг хэмжих) | Босго | Цонх / нөхцөл |
|---|---|---|---|
| Performance | `/cart/add` latency | p95 < 200 ms | 20 VU, 1 минут |
| Reliability | `/pay` error rate | < 8% | 20 VU, 1 минут |
| Availability | Нийт амжилттай хүсэлтийн хувь | ≥ 90% | 2 минут, 10 секундийн зогсолт |

### Босго сонгосон үндэслэл

- **Performance:** `/cart/add` нь энгийн локал үйлдэл тул p95 хариу хугацааг 200 ms-ээс бага байхаар сонгов.
- **Reliability:** `/pay` endpoint-д ойролцоогоор 5% санамсаргүй алдаа зориудаар үүсгэсэн тул 8%-ийн босго нь бодитой гэж үзэв.
- **Availability:** 2 минутын туршилтын үед серверийг 10 секунд зогсоох тул нийт хүсэлтийн хамгийн багадаа 90% амжилттай байх босгыг сонгов.

### Error budget

Availability SLO = 90%

Error budget = 100% - 90% = 10%

2 минут = 120 секунд

120 × 0.10 = 12 секунд

Иймээс 2 минутын цонхонд системийн хугацаагаар тооцсон error budget нь **12 секунд** байна.

k6 тестийг 20 VU ачаалалтайгаар 1 минут ажиллуулсан.

| Үзүүлэлт | SLO босго | Бодит үр дүн | Төлөв |
|---|---|---|---|
| `/cart/add` p95 latency | < 200 ms | 3.04 ms | PASS |
| `/report` p95 latency | < 450 ms | 390.19 ms | PASS |
| `/pay` error rate | < 8% | 4.52% | PASS |
| Checks success rate | > 90% | 98.49% | PASS |

Нийт 2784 HTTP хүсэлт илгээгдсэн бөгөөд 42 хүсэлт амжилтгүй болсон. `/pay` endpoint-ийн 928 хүсэлтээс 42 нь алдаатай байсан тул error rate 4.52% гарсан. Бүх threshold тавьсан SLO босгыг хангаж PASS болсон.
## Chaos test үр дүн

Chaos test-ийг 20 VU, 2 минутын хугацаатай ажиллуулж, тестийн явцад серверийг ойролцоогоор 10 секунд зогсоогоод дахин асаасан.

- Нийт хүсэлт: 5715
- Амжилттай check: 4858
- Амжилтгүй check: 857
- Check success rate: 85.00%
- /cart/add p95: 2.72 ms
- /report p95: 390.32 ms
- /pay error rate: 17.84%

Availability-ийн SLO нь ≥ 90% байсан боловч бодит үр дүн 85.00% гарсан тул availability threshold FAIL болсон.

Reliability-ийн хувьд /pay error rate < 8% байх ёстой байсан боловч 17.84% гарсан тул мөн FAIL болсон. Үүнд /pay endpoint-ийн өөрийн санамсаргүй алдаанаас гадна серверийг түр зогсоосон хугацаанд үүссэн хүсэлтийн алдаанууд нөлөөлсөн.

2 минутын хугацаанд availability SLO 90% тул time-based error budget:

120 секунд × 10% = 12 секунд.

Харин request-based хэмжилтээр 5715 хүсэлтээс 857 нь амжилтгүй болсон тул бодит success rate 85.00% байна. Time-based error budget болон request-based availability нь ижил хэмжигдэхүүн биш учраас серверийг ойролцоогоор 10 секунд зогсоосон ч хүсэлтийн тархалт болон тухайн үеийн алдаанаас шалтгаалан request-based availability 90%-иас доош орж болно.
