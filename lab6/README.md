## 3. A хэсэг: Category-Partition

### A1. Сонголт ба төлөөлөх утгууд

Банкны шилжүүлгийн API дараах хүсэлтийг хүлээн авна.

`POST /transfer`

Хүсэлтийн бүтэц:

```json
{
  "from": 1001,
  "to": 1002,
  "amount": 50000,
  "currency": "MNT"
}
```

Шилжүүлэг амжилттай бол HTTP `201` статус болон `{"result":"OK"}` хариу буцаана.

Алдаа гарсан тохиолдолд HTTP `200` статус болон тухайн алдааг илэрхийлэх `result` утга буцаана.

Тестийн үндсэн параметрүүдийг `From`, `To`, `Amount`, `Currency` гэж тодорхойлов.

| Параметр | Сонголт | Төлөөлөх утга | Тайлбар |
|---|---|---|---|
| From | Valid | 1001 | Хүчинтэй, царцаагдаагүй данс |
| From | Frozen | 1003 | Царцаагдсан данс |
| From | Missing | 9999 | Системд бүртгэлгүй данс |
| To | Valid | 1002 | Хүчинтэй, шилжүүлэгчээс өөр данс |
| To | Missing | 9998 | Системд бүртгэлгүй хүлээн авагч |
| To | SameAsFrom | `from`-той ижил ID | Өөрийн данс руу шилжүүлэх |
| Amount | Zero | 0 | Шилжүүлэх дүн тэг |
| Amount | Negative | -100 | Шилжүүлэх дүн сөрөг |
| Amount | Normal | 50000 MNT | Үлдэгдэл болон лимитэд багтсан дүн |
| Amount | OverBalance | 2000000 MNT | Үлдэгдлээс хэтэрсэн дүн |
| Amount | OverLimit | 1500000 MNT | Өдрийн үлдсэн лимитээс хэтэрсэн дүн |
| Currency | Same | MNT | Дансны үндсэн валют |
| Currency | Different | USD | Валют хөрвүүлэх шаардлагатай |

**Тайлбар:** Amount-ийн төлөөлөх утгууд нь MNT валюттай үндсэн жишээ юм. `Currency=Different` үед валютын ханш болон дансны үлдэгдэл, лимитэд тохируулан тусдаа дүн ашиглана.

### A2. Сонголтын хязгаарлалтууд

Category-Partition аргаар тестийн нөхцөлүүдийг тодорхойлохдоо `[ERROR]`, `[SINGLE]`, `[IF]` тэмдэглэгээг ашиглав.

- **[ERROR]** — алдаа үүсгэх сонголт.
- **[SINGLE]** — тусад нь шалгах шаардлагатай сонголт.
- **[IF]** — бусад параметрийн утгаас хамаарах хязгаарлалт.

| Параметр | Сонголт | Тэмдэглэгээ | Үндэслэл |
|---|---|---|---|
| From | Valid | Энгийн | Шилжүүлэг хийх боломжтой данс |
| From | Frozen | [ERROR] | Царцаагдсан данснаас шилжүүлэг хийх боломжгүй |
| From | Missing | [ERROR] | Шилжүүлэгч данс байхгүй |
| To | Valid | Энгийн | Хүчинтэй хүлээн авагч |
| To | Missing | [ERROR] | Хүлээн авагч данс байхгүй |
| To | SameAsFrom | [ERROR], [IF From=Valid] | Өөрийн данс руу шилжүүлэхийг хориглоно |
| Amount | Zero | [ERROR] | Дүн тэгээс их байх ёстой |
| Amount | Negative | [ERROR], [SINGLE] | Сөрөг дүнг тусгайлан шалгана |
| Amount | Normal | Энгийн | Үлдэгдэл болон лимитэд багтсан |
| Amount | OverBalance | [ERROR] | Үлдэгдэл хүрэлцэхгүй |
| Amount | OverLimit | [ERROR] | Өдрийн үлдсэн лимит хүрэлцэхгүй |
| Currency | Same | Энгийн | Валют хөрвүүлэх шаардлагагүй |
| Currency | Different | Энгийн | Хөрвүүлсэн дүнгээр үлдэгдэл, лимитийг шалгана |

#### A2.1. IF хязгаарлалтууд

**IF-1:**

`To=SameAsFrom` бол `From=Valid` байна.

Энэ нь өөрийн данс руу шилжүүлэх алдааг тусад нь шалгах үед хүчинтэй эх данс ашиглах зорилготой.

**IF-2:**

`From=Missing` үед `Amount=OverBalance` эсвэл `Amount=OverLimit` сонголтыг ашиглахгүй.

Учир нь эх данс байхгүй үед тухайн дансны үлдэгдэл болон өдрийн лимитийг шалгах боломжгүй.

Эдгээр нь тестийн загварчлалд сонгосон хязгаарлалтууд бөгөөд API-ийн бүх боломжит хүсэлтийг хориглож байгаа гэсэн үг биш юм.

#### A2.2. Хослолын тооцоо

Дөрвөн параметрийн сонголтын тоо:

| Параметр | Сонголтын тоо |
|---|---:|
| From | 3 |
| To | 3 |
| Amount | 5 |
| Currency | 2 |

Хязгаарлалтгүй нийт хослол:

**N = 3 × 3 × 5 × 2 = 90**

Python-ийн `itertools.product` ашиглан бүх хослолыг үүсгэж, хоёр IF хязгаарлалтыг шалгав.

| Үзүүлэлт | Хослолын тоо |
|---|---:|
| Хязгаарлалтгүй нийт хослол | 90 |
| IF-1 нөхцөлөөр хасагдсан | 20 |
| IF-2 нөхцөлөөр хасагдсан | 12 |
| Давхар тоологдсон хасалт | 4 |
| Хязгаарлалтын дараах хослол | 62 |

Давхардсан хасалтыг нэг удаа тооцвол:

**M = 90 − (20 + 12 − 4) = 62**

Иймээс:

**N → M = 90 → 62**

Энэ нь зөвхөн хоёр IF хязгаарлалтын дараах хослолын тоо юм. `[ERROR]` болон `[SINGLE]` тэмдэглэгээг тестийн сонголт, тусгай тестийн спецификацид ашиглана.

Тооцоог `count_combinations.py` скриптээр шалгасан.

### A3. Тестийн спецификацийн хүснэгт

Тестийн спецификацийг боловсруулахдаа амжилттай шилжүүлэг, алдааны бүх ангилал болон олон алдаа зэрэг үүссэн нөхцөлийг хамруулав.

#### A3.1. Алдааны давуу эрэмбэ

Олон алдаа зэрэг үүссэн үед дараах давуу эрэмбийг сонгов.

`ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT`

Эхлээд шилжүүлэгч данс, дараа нь хүлээн авагч данс, эцэст нь шилжүүлгийн дүн болон лимитийг шалгана.

Энэхүү эрэмбэ нь лабораторийн тестийн oracle-д зориулан сонгосон дүрэм юм. API-ийн бодит хэрэгжүүлэлтэд алдааны давуу эрэмбэ тодорхой заагдаагүй.

#### A3.2. Тестийн спецификаци

| ID | From | To | Amount | Currency | HTTP статус | Result |
|---|---|---|---|---|---|---|
| TC01 | Valid | Valid | Normal | Same | 201 | OK |
| TC02 | Valid | Valid | Normal | Different | 201 | OK |
| TC03 | Missing | Valid | Normal | Same | 200 | ERROR_NO_FROM |
| TC04 | Frozen | Valid | Normal | Same | 200 | ERROR_FROZEN |
| TC05 | Valid | Missing | Normal | Same | 200 | ERROR_NO_TO |
| TC06 | Valid | SameAsFrom | Normal | Same | 200 | ERROR_SAME_ACCOUNT |
| TC07 | Valid | Valid | Zero | Same | 200 | ERROR_BAD_AMOUNT |
| TC08 | Valid | Valid | Negative | Same | 200 | ERROR_BAD_AMOUNT |
| TC09 | Valid | Valid | OverBalance | Same | 200 | ERROR_INSUFFICIENT |
| TC10 | Valid | Valid | OverLimit | Same | 200 | ERROR_LIMIT |
| TC11 | Frozen | Missing | Normal | Same | 200 | ERROR_FROZEN |
| TC12 | Valid | Missing | Zero | Same | 200 | ERROR_NO_TO |

TC01 болон TC02 нь амжилттай шилжүүлгийг шалгана.

TC03–TC10 нь алдааны бүх ангиллыг хамарна.

TC08 нь `[SINGLE]` тэмдэглэгээтэй сөрөг дүнгийн тусгай тест юм.

TC11 болон TC12 нь олон алдаа зэрэг үүссэн нөхцөлд давуу эрэмбийн дагуу аль алдааг буцаахыг шалгана.

#### A3.3. Тестийн орчны тодорхойлолт

Тестийн үр дүнг хоёрдмол утгагүй болгохын тулд дараах жишиг өгөгдлийг ашиглана.

| Нөхцөл | Утга |
|---|---|
| Шилжүүлэгч данс | 1001 |
| Хүлээн авагч данс | 1002 |
| Царцаагдсан данс | 1003 |
| Байхгүй шилжүүлэгч данс | 9999 |
| Байхгүй хүлээн авагч данс | 9998 |
| Дансны үндсэн валют | MNT |
| Жишиг валютын ханш | 1 USD = 3500 MNT |

Amount-ийн сонголт бүрт тохирох орчныг дараах байдлаар бэлтгэнэ.

| Amount сонголт | Шилжүүлэх дүн | Үлдэгдэл | Өдрийн үлдсэн лимит | Хүлээгдэх үр дүн |
|---|---:|---:|---:|---|
| Normal | 50000 MNT | 1000000 MNT | 1000000 MNT | OK |
| Zero | 0 MNT | 1000000 MNT | 1000000 MNT | ERROR_BAD_AMOUNT |
| Negative | -100 MNT | 1000000 MNT | 1000000 MNT | ERROR_BAD_AMOUNT |
| OverBalance | 2000000 MNT | 1000000 MNT | 3000000 MNT | ERROR_INSUFFICIENT |
| OverLimit | 1500000 MNT | 2000000 MNT | 1000000 MNT | ERROR_LIMIT |

**OverBalance:** Дансны үлдэгдэл хүрэлцэхгүй боловч өдрийн үлдсэн лимит хангалттай байна.

**OverLimit:** Дансны үлдэгдэл хангалттай боловч өдрийн үлдсэн лимит хүрэлцэхгүй байна.

**Currency=Different:** Шилжүүлгийн дүнг USD-ээр өгч, MNT-д хөрвүүлсний дараа үлдэгдэл болон лимитийг шалгана.

Жишээлбэл, TC02 тестэд:

- Шилжүүлэх дүн: 100 USD
- Хөрвүүлсэн дүн: 350000 MNT
- Дансны үлдэгдэл: 1000000 MNT
- Өдрийн үлдсэн лимит: 1000000 MNT
- Хүлээгдэх HTTP статус: 201
- Хүлээгдэх result: OK

Ингэснээр TC02 тестэд валютын хөрвүүлэлт хийгдсэн ч шилжүүлэг амжилттай болно.

Эдгээр нь бодит банкны өгөгдөл биш, тестийн зориулалтаар сонгосон жишиг утгууд юм.
